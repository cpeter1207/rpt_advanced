# BS.1770 measurement in the existing AGC - confirmed requirements

**Objective:** Extend the existing AGC in the `usbradioplus_agc_lufs` Rust LADSPA plugin to include a BS.1770 loudness detector replacing RMS while reusing its existing gain rider and silence/activity controls as required by the user: "I want to replace rms with lufs in the AGC.".

**Confirmed Behavior:**
1. **Detector replacement:** Introduce a BS.1770 loudness detector replacing RMS with a target of -23 LUFS. Use `agc_target_lufs=-23`; there is no detector-mode switch or legacy RMS target alias. Remove the RMS target and averaging controls. Rename the profile settings to `agc_target_lufs` (default -23) and `agc_loudness_window_ms` (default 3000, range 400-3000); retain the independent raw activity gate in dBFS.
2. **Metering:** The AGC measures its full-band input before RF preemphasis and CTCSS. The user additionally requested an independent gated integrated loudness and true-peak output meter, and explicitly selected keeping the rolling LUFS AGC. The output reference is the final mono programme graph output, after graph filtering/gain/limiting and any oversampling return to 48 kHz, before calibration/test signals, access tones, and hardware mixer scaling.
3. **Gain policy:** Reuse the existing per-sample ramp, rise/fall rates, boost/attenuation caps, activity gate, hold, and deadband. Keep gain unchanged during silence and until a valid loudness observation exists. The default three-second rolling analysis advances with every delivered sample, using zero during inactivity. Renewed activity preserves history; only activation, a new instance, or a window change requires a complete initial window. PTT releases count as silence through the existing graph owners, including intervals without delivered PCM; do not add a LADSPA port or another gain application. Retain defaults of 2 dB/s increase, 6 dB/s reduction, 500 ms gain-increase hold, 1 dB deadband, and the separate 10 ms raw activity detector. Inactivity restarts boost qualification without resetting the loudness window.
4. **Measurement and protection:** Use actual mono K-weighted measurement, including BS.1770 absolute/relative gating for integrated readings. Use valid momentary/short-term observations for causal gain riding and verify integrated output independently. Target -23 LUFS, with the EBU live-program aim of +/-1 LU where meaningful. Retain transmitter limiting and verify the -1 dBTP output ceiling independently; metering alone does not limit peaks. Brief bursts, silence, and correction caps cannot promise exact integrated loudness.
5. **G.169 timing:** ITU-T G.169 (05/2011) does not prescribe a three-second window or a fixed speech attack/release pair. Appendix I.3.2 favors longer time constants; section 7.1.2 bounds gain increase at 10 dB/s in its echo-cancelled-network scenario, and section 7.4.1 Method 1 screens attenuation below 10 dB/s for DTMF. Retain the 2/6 dB/s defaults without claiming full G.169 qualification.
6. **Realtime Constraints:** The AGC and output meter do not buffer or delay programme audio. Oversampling around the existing lookahead limiter may add bounded resampling delay; measure it, account for draining/handoffs, and preserve PTT start/release behavior. No callback allocation, locks, or logging in the new Rust analysis code.

**Implementation Details:**
1. **LADSPA Plugin Extension:** Modify the existing `usbradioplus_agc_lufs` graph-hosted plugin to add the detector; retain one gain application. Feed its BS.1770 detector from the full program rather than the current 800-1500 Hz RMS sidechain.
2. **Configuration Management:** Use the existing shared-profile resolution in USBRadioPlus and rpt_advanced. Begin with the current local/link/voice processing settings, choose the AGC position so later dynamics do not defeat the target, and preserve hardware gain, RF calibration, preemphasis, CTCSS, and routing.
3. **Metering and Detection:** Prefer the MIT-licensed Rust `ebur128` 0.1.11 implementation inside the existing owned plugin, using fixed histogram mode and setup-allocated analysis storage. Source review supports this candidate; a native build and callback allocation checks remain mandatory.
4. **Lifecycle:** Keep analyzer state per graph instance. Prepare/reset state without allocation during processing; reload preserves generation ownership and never restarts Asterisk for a configuration change.
5. **Output Verification:** Independently measure the processed program. Use FFmpeg resampling around the existing final limiter, with factors 1, 2, or 4 (default 4, giving 192 kHz at native 48 kHz), and verify the final 48 kHz programme true peak against -1 dBTP. Place the optional bandpass, preemphasis, and all graph gains before final protection; meter after the return to native rate and audible handoff selection. Preserve existing calibrated ceilings. The internal sample ceiling is not a dBTP guarantee for arbitrary signals. A 192 kHz sample ceiling alone is insufficient: downsampling and subsequent filtering can create overshoot. Keep protection distinct from gain riding and preserve RF calibration.
6. **Scope:** Reuse the existing graph owners and diagnostics for the integrated output meter and maximum true peak. Meter only the audible final output, including crossfades, and exclude graph warmup. Retain integration through silence; use BS.1770 absolute/relative gating, publish an explicit unmeasured state before sufficient data, and document the graph-generation/reset epoch. Avoid a new UI, plugin registry, or external adapter ABI solely to obtain readings.
7. **Configuration Audit:** Replace RMS units/settings in the existing AGC and remove its obsolete narrow-band detector-filter settings. Preserve hardware gain settings and other dynamics sidechains.

**Validation:**
1. **Independent FFmpeg Measurements:** Conduct independent FFmpeg measurements and EBU vectors.
2. **Convergence/Ramp/Cap Tests:** Perform convergence, ramp, and cap tests.
3. **Silence and Short-Transmission Warmup:** Test the default three-second startup, silence advancing history without resetting it, short transmissions, and PTT releases/rekeys including no-PCM gaps. Verify the 500 ms boost hold independently of the initial window and retain gain during inactivity.
4. **Reload and PTT Regressions:** Verify reload and PTT regressions.
5. **Build/Install/Health Checks:** Run the repository-required Debian 13 amd64/arm64 checks, including required production coverage, packaging, staged installation, and callback allocation checks. Build natively under /home/asl3 for node524950.local. Install the exact tested source/artifact set with backups, hashes, configuration validation, service-health/log checks, and rollback. Preserve unrelated local work.
6. **Authorization:** The original request already authorizes build, test, settings changes, and installation on node524950.local. The user confirmed replacement of RMS with LUFS after the proposed AGC-reuse approach. Continue through the originally authorized build, test, settings changes, and node installation.

**Alternatives:**
1. **Settings only:** Existing RMS AGC and fixed gains can be calibrated using external loudness measurements, but cannot provide a genuine BS.1770 detector through target settings alone.
2. **Stock FFmpeg loudnorm:** Its dynamic mode buffers approximately three seconds. Inline ebur128 metadata/true-peak mode collects 100 ms frames. These do not fit the existing live callback contract. Retain FFmpeg as the graph host, use existing graph stages, and extend the existing AGC for the missing causal control.

**Remaining Verification:**
1. **Realtime Guarantees:** Verify the realtime guarantees of the loudness detector.
2. **Peak protection:** Verify the retained limiting independently; gain riding and peak limiting remain separate graph responsibilities.

**Recommendation:** Reuse the existing AGC extension for the proposed behavior. Address the remaining verification points to ensure the design meets all constraints.
